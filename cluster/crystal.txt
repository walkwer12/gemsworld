A. Initial setup – One-time checks
Open PowerShell.
1. Check Python
python --version
2. Check Docker
docker --version
docker compose version
3. Check Docker is running
docker info
4. Check Kafka Python library
python -m pip show kafka-python
If it is not installed:
python -m pip install kafka-python
Confirm:
•	Python is accessible.
•	Docker Desktop is running.
•	Docker Compose is available.
•	kafka-python is installed.
Do not reinstall Python or Docker if everything is working.
B. Create project folder
PowerShell
mkdir BD_P3
cd BD_P3
Open this folder in VS Code:
code .
Create the following files:
BD_P3/
│
├── docker-compose.yml
├── Producer.py
└── Consumer.py
C. Configure the three-broker Kafka cluster
Create docker-compose.yml.
D. Start Kafka cluster
PowerShell – Terminal 1
Make sure you're inside BD_P3.
docker compose up -d
Wait for the containers to initialize.
Check:
docker compose ps
Expected result:
You should see three containers:
Container	Expected state
kafka1	Running
kafka2	Running
kafka3	Running
Check logs if required:
docker logs kafka1
docker logs kafka2
docker logs kafka3
Do not proceed if the containers are repeatedly restarting.
E. Create Producer.py
F. Create Consumer.py
G. Execute Consumer
PowerShell – Terminal 2
Open a second VS Code terminal.
Navigate to the project folder if necessary:
cd BD_P3
Run:
python Consumer.py
Wait until you see:
Consumer started...
Waiting for messages...
IMPORTANT: Keep this terminal running. The consumer continuously waits for incoming messages.
H. Execute Producer
PowerShell – Terminal 3
Open a third terminal.
cd BD_P3
Run:
python Producer.py
Expected output:
Produced: {'student_id': 1, ...}
Produced: {'student_id': 2, ...}
Produced: {'student_id': 3, ...}
...
Produced: {'student_id': 10, ...}
The producer sends 10 messages, waiting one second between messages.
Switch to Terminal 2.
Expected consumer output:
Consumer started...
Waiting for messages...

Received: {'student_id': 1, ...} | Partition: 0 | Offset: 0
Received: {'student_id': 2, ...} | Partition: 0 | Offset: 1
...
The exact partition and offset values depend on topic configuration and message distribution. The example above is illustrative.
Expected result
All 10 student messages should be received by the consumer.

I. Verify Docker containers and Kafka logs
PowerShell
docker compose ps
Check the broker logs:
docker logs kafka1
docker logs kafka2
docker logs kafka3
You can also inspect the containers in Docker Desktop.
Expected:
•	Three Kafka containers.
•	All three running.
•	Kafka broker logs without repeated startup failures.
J. Successful execution checklist
•	Python is installed.
•	Docker Desktop is running.
•	kafka-python is installed.
•	Project folder BD_P3 is created.
•	docker-compose.yml is configured.
•	Three Kafka brokers start successfully.
•	All three containers show Running.
•	Producer.py executes successfully.
•	Ten student messages are generated.
•	Consumer.py executes successfully.
•	Consumer receives all ten messages.
•	Partition and offset information is displayed.
K. Troubleshooting
Error	What to do
ModuleNotFoundError: No module named 'kafka'	Run python -m pip install kafka-python.
Docker daemon is not running	Start Docker Desktop and retry.
docker compose not recognized	Check Docker Compose availability with docker compose version.
Port already allocated	Check which process/container is using 29092, 39092 or 49092.
NoBrokersAvailable	Check all three containers and their logs. Verify advertised listeners and port mappings.
Connection refused	Ensure Kafka has finished starting before running Python.
Consumer waiting indefinitely	Start the producer in another terminal.
Consumer receives no old messages	Check group_id and committed offsets. For a fresh test, use a new group ID or reset the existing group offsets.
Containers repeatedly restart	Run docker compose logs and inspect the first startup error.
YAML parsing error	Check indentation. YAML uses spaces, not tabs.
L. Stop the Kafka cluster
After successfully completing the practical:
PowerShell – Terminal 1
docker compose down
This stops and removes the containers and Compose network. No persistent volumes are configured in the supplied Compose file.
